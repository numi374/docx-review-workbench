# DOCX 校对工作台

## 在线使用

[打开 DOCX 校对工作台](https://numi374.github.io/docx-review-workbench/)。

Word 文件由浏览器内的 WebAssembly 处理。文件、历史和批注保存在当前浏览器的 IndexedDB。工作台使用 GitHub Pages 提供程序资源。若要把本机工作台的旧项目带到网页版，请在本机导出项目 ZIP，再在网页版恢复。

## 本机启动

Windows 双击 **Start.cmd**，然后在 [本地工作台](http://127.0.0.1:4177/) 创建项目。选择原文、第一轮二校稿和可选的修改说明。运行需要 Node.js 24 和支持选区及 CSS 高亮 API 的 Edge 或 Chrome。从源码启动时，先安装依赖并构建。构建完成后，本机版可以断网运行。

也可在当前目录执行 `node serve.mjs`，然后访问同一个本地地址。最后关闭启动窗口即可停止服务。请通过同一个地址和浏览器配置文件访问，以恢复 IndexedDB 中的文件和批注。

## 复核流程

1. 点击高亮或用修改导航选择一处修改。右侧显示前后内容、关联状态和 Codex 原因。「修改说明」包含全部记录和全文，可筛选未匹配项、关联到当前修改或解除关联。已创建的轮次也可导入或替换说明，支持 DOCX、Markdown 和 TXT。换用不同的说明文件会重新匹配本轮说明。
2. 在任一栏的同一段落内选中文字，然后点击「添加批注」。列表支持查看、编辑、删除、定位和状态筛选。Alt+↑ / Alt+↓ 跳转修改，Ctrl+Enter 保存批注。
3. 点击「生成反馈」，勾选需要的批注并预览 Markdown。待处理且可定位的批注默认选中，已确认的批注默认排除。复制、导出或保存时会留下本轮反馈快照。待重新定位的历史批注可手动勾选，报告会提示其位置和引文来自历史轮次。
4. 点击「导入新轮次」，默认以上一轮二校稿为基准，也可选择最初原文。上一轮待处理批注在新轮生成独立复核项。能在新二校稿唯一确认整段文字和选区的批注会恢复定位，其余标记为「待重新定位」。点击该项的「重新定位」，再选取本轮文档文字。复核完成可点击「确认已处理」。
5. 「历史版本」可以打开旧轮次和旧反馈，并下载 ZIP 项目备份。恢复时校验文件哈希并另存为一个项目。原始文档副本按文件内容去重保存，所有轮次和批注互相独立。旧原型存下的最近一组文件和批注会在同浏览器配置和同地址上迁移为第一轮。

单文件导入上限 25 MB，项目备份上限 384 MB。浏览器存储配额不足时会提示失败。清理站点数据、换浏览器配置或换电脑前，可先下载项目备份。

源代码重建需联网安装依赖。在此目录运行 `npm ci`、`npm run build` 和 `node serve.mjs`。完成构建后，也可以双击启动脚本。

## 两个项目能复用什么

| 能力 | Docxodus 13.0.0 | docx-diff |
| --- | --- | --- |
| DOCX 解析 | 在 WASM 中通过 Open XML 读取 DOCX 的部件、段落、样式、表格和修订。引擎 API 接受原始字节。 | 利用同一引擎。其 OOXML 辅助代码用于规范化文本、标记修订、提取元数据和组装导出。 |
| 格式还原 | `convertDocxToHtml` 可输出标题、列表、段落、行内样式、表格、图片、脚注和尾注，另有独立的页眉页脚及分页选项。 | 将一份带修订的 HTML 显示为不同栏，按栏隐藏对应插入或删除，处理段落拆分／合并，并隔离文档样式。 |
| 比较 | `docxDiffCompare` 生成含原生 Word 修订的 DOCX；`getRevisions` 返回修订类型、内容和受影响的锚点。 | 把相邻的删除和插入组成替换，处理空段落标记和脚注关联，归并等价文本的格式变化。 |
| 定位 | `stampAnchors` 输出块锚点。修订记录包含所属部件和受影响块。 | 使用修订标记到 DOM 的映射，定位改动并通过共同可见块计算同步滚动位置。 |
| 批注和评论 | `getComments` 读取原有 Word 评论，转换器可行内或边栏呈现。会话的 `addComment` 支持写入指定段落选区。外部注释 API 支持原始 DOCX 的文本投影、哈希校验和高亮。 | 审阅评论按修改项保存，可随导出写入 Word。其状态结构面向每项修改的接受／拒绝和评论。 |

API 来自 [Docxodus v13 文档](https://github.com/JSv4/Docxodus/blob/v13.0.0/docs/npm-package.md)。比较视图来自 [docx-diff 架构文档](https://github.com/docx-diff/docx-diff/blob/9b942f6432e30584bd6fa8a33dcb0fb56aea7025/docs/architecture.md)。这两个项目均采用 MIT 许可证，保留的声明在 `licenses/`。复用代码基于 docx-diff 提交 `9b942f6432e30584bd6fa8a33dcb0fb56aea7025`。

## 实测结果

- Windows 上用 Node.js 24.18.0、npm 11.16.0 编译了原型并在 Edge 运行。Docxodus npm 包已包含 .NET/WASM 运行时。本机没有安装 .NET SDK。运行产物大约 26 MB，浏览器只请求本机资源。
- docx-diff 上游声明 Node.js `^24.22.0`。本机直接 `npm ci` 遇到版本限制；放开版本检查后还遇到锁文件缺少 Rollup 可选平台条目。仅在调研副本用 `npm install --engine-strict=false` 重新解析依赖，已成功构建并在 Edge 完成一次对比。选跑的引擎、修订标记和修改分组测试共 28 项通过。原型拥有自己的锁文件。
- 用上游真实编辑样本 aramlo 第二卷的完整原稿和部分二校稿，在浏览器识别 598 项修改，与上游基准一致。比较、修订索引和转换约耗时 7.5 秒。验证了顺序导航、指定跳转及同步滚动。样本二校稿包含 76 个正文段落，未覆盖的原稿后半部在完整文档对比中显示为删除。
- 用小型 OOXML 文档额外覆盖了中文、英文 SLA 文本、标题、加粗、斜体、列表、空段落、合并表格单元格及段落拆分。原型仅标记中文改词以及表格数字 `24 → 12` 的变化区间。原有 Word 评论可读取，鼠标选区批注在刷新和重新打开页面后精确恢复。损坏的 DOCX 导入报错，当前记录仍可恢复。
- Node 端重复比较同一对 DOCX，检验了红线文件 SHA-256 和修订 ID 的一致性。原有 Word 评论可读，一次会话内新增评论可写到新字节。独立 DOCX 的外部注释投影和不同文件哈希失配也已验证，原始输入字节哈希保持一致。

真实样本及其基准数据来自 [docx-diff 样本测量](https://github.com/docx-diff/docx-diff/blob/9b942f6432e30584bd6fa8a33dcb0fb56aea7025/docs/measurements.md)。

## 工作台实现

1. **引擎和对比**沿用固定版本的 Docxodus WASM 和 docx-diff 模块。浏览器 Worker 从本机加载 WASM，处理比较、修订、HTML 和 Word 原有评论。
2. **说明匹配**读取带字段的段落、编号记录和表格。先比较修订前后引文，再核对段落上下文和位置，重复引文若缺少可区分的证据，会交由人工确认。引文重复或证据不足时保留为未匹配。人工解除关联后，重开轮次仍保持未匹配。
3. **批注和反馈**保存文件哈希、所在栏、块锚点、字符范围、选中文字、段落上下文、处理状态及修改关联。反馈包含具体选区、章节、段落或表格位置，列出基准稿和当前稿的完整对应段落。
4. **历史和备份**在 IndexedDB 中分别存项目与按 SHA-256 索引的文件副本。每轮保存说明关联覆盖项、批注及反馈快照。项目更新使用事务和版本检查，避免两个页面覆盖对方的修改。ZIP 内含项目清单、原文、各轮文件和反馈。

当前 HTML 是流式阅读视图。页眉页脚对比关闭，复杂分页、节布局、文本框、公式及精细样式还原需要单独验收。含原生修订的输入按接受修订后的视图比较。人工批注目前使用单段选区，跨轮次只在整段和引文可验证时恢复。

## 复跑本轮验收

- 匹配与歧义测试运行 `node --test qa/notes.test.mjs`。
- 安装 Python 的 `python-docx` 和 `playwright`，启动工作台后运行 `python -B qa/workbench.py`。测试使用真实 OOXML 文件、鼠标选区和 Edge 剪贴板，检查 Markdown 下载、三轮历史、批注迁移、重启恢复、ZIP 备份和错误回退。
- 为上游真实样本指定目录可一并复跑 598 处修改和同步导航检查。参数为 `--samples <docx-diff docs 目录>`。

## 代码入口

- `src/engine.worker.js` 调用 Docxodus，把带修订和锚点的 HTML 发送给页面。
- `src/upstream/` 保留的 docx-diff 模块及来源说明。
- `src/app.js` 渲染双栏、修改导航和本地记录。
- `src/anchors.js` 从浏览器选区计算可见文本偏移并恢复批注。
- `src/contexts.js` 建立双栏段落证据，核对跨轮批注位置。
- `src/notes.mjs` 和 `src/feedback.mjs` 解析、匹配修改说明并生成反馈。
- `src/storage.js` 管理 IndexedDB、文件去重、历史和项目备份。
- `verify-engine.mjs` 面向内含中文句子、列表、表格及 Word 评论的验证样本，测试原生和外部注释 API。

可选复跑 API 检查。安装 Python 的 `python-docx` 后，运行 `python qa/fixtures.py` 生成验证 DOCX。完成 npm 依赖安装后运行 `node verify-engine.mjs qa/original.docx qa/reviewed.docx`。
